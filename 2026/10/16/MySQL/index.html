Windows 下 MySQL 8.0 安装、配置及 Workbench 连接实战

核心技术栈

MySQL 是一个基于客户端-服务器（C/S）架构的开源关系型数据库管理系统（RDBMS）。

1.关系型数据模型（Relational Model）

数据以二维表（Table）的形式组织，表与表之间可以通过主键（Primary Key）和外键（Foreign Key）建立关联关系。它使用结构化查询语言（SQL）作为交互接口。

2.C/S 架构与多线程模型

MySQL 由服务端守护进程（mysqld）和客户端工具（如 mysql CLI, Workbench, JDBC）组成。服务端采用多线程架构，每个客户端连接对应一个专属线程，配合线程池管理高并发请求。

3.插件式存储引擎（Pluggable Storage Engine）

这是 MySQL 区别于其他数据库（如 PostgreSQL）的核心架构特征。MySQL 的 SQL 层与底层数据存储解耦。默认且最常用的存储引擎是 InnoDB（支持 ACID 事务、行级锁、MVCC 多版本并发控制、B+树索引）；此外还有 MyISAM（表级锁，适合读多写少）、Memory 等引擎。

4.跨平台与多语言支持

采用 C/C++ 编写，支持 Windows、Linux、macOS 等主流操作系统。同时提供 C API、JDBC、ODBC、Python、Go 等几乎所有主流编程语言的驱动。

5.开源与双授权模式

遵循 GPL 协议，社区版完全免费，同时提供商业版授权及企业级支持。

04 DQL数据操作

1.查看刚写进去的数据:

例：select * from employee;

查询员工表所有列所有行
*号表示”所有列”，但实际开发中不推荐用 *，
因为性能低（查了不需要的列） ，代码可读性差 ，表结构变了查询结果也变。

2.列别名:

给列起个好懂的别名，结果表头显示中文
as 可以省略，直接空格写别名。

3.distinct 去重:

查询结果中重复的行只保留一条，比如查有哪些部门，不要每个部门重复显示。
注：as 给列起别名让结果好看，distinct 去掉重复行

4.where：只查满足条件的行：

例：查工资大于10000的员工
select name, salary from employee where salary > 10000;
执行顺序：先 from 找到表 → 再 where 筛选行 → 最后 select 取列。
常用比较运算符：= 等于、> 大于、< 小于、>= 大于等于、<= 小于等于、!= 不等于

5.AND / OR / NOT ：组合多个条件:

  • AND 并且（同时满足）
  • OR 或者（满足一个）
  • NOT 取反

6.LIKE：模糊匹配字符串:

注：% 是”任意多”，_ 是”一个”。搜索框的功能就是这个
7.in / between / is null :

  • in 在多个值里:

等于这些值中任意一个就行
相当于 where dept=’技术’ or dept=’产品’ or dept=’运营’

  • between 范围:

在某个闭区间内（包含两端）
相当于 salary>=8000 and salary<=15000

  • is null 是空值:

判断是不是NULL（空值）
注意：不能用 = null，必须用 is null

8.ORDER BY：按某列排序

例：按工资从高到低排序
select name, salary from employee order by salary desc;

asc 升序(从小到大，默认) 　
desc 降序（从大到小）

不写默认是 asc
可以多列排序：order by salary desc, age asc（先按工资降序，工资相同再按年龄升序）
order by 永远写在语句最后面。

9.LIMIT：分页查询（必学）：

例：每页10条，查第1页和第2页
– 第1页：前10条 select * from emp order by id limit 0, 10;
– 第2页：第11到20条 select * from emp order by id limit 10, 10;

公式：第n页 limit (n-1)*每页条数, 每页条数
网站上”下一页”按钮背后就是这个，开发必用。

where 和 having 的区别：
· where：分组前过滤行，不能用聚合函数
· having：分组后过滤组，可以用聚合函数

语句顺序：from → where → group by → having → select → order by → limit

15.inner join：标准内连接写法

和前面 where 写法的区别：
效果完全一样，只是写法不同，inner join 更清晰

17.子查询：查询套查询
例：查工资比”张三”高的员工？

执行逻辑：

  1. 先执行括号里的子查询：查出张三的工资（比如8000）
  2. 再执行外层查询：查工资大于8000的员工

UNION：把两个查询的结果上下拼在一起
· union 会去重，union all 不去重（性能更好）

05 约束与索引

1.PRIMARY KEY：主键约束
– 建表时指定主键

主键的两个特点：
· 唯一性：不能有两行id相同
· 非空性：id不能是NULL

实战建议：每张表都应该有一个id列作为主键，这是行业惯例
2.FOREIGN KEY：外键约束
作用：表和表之间建立关联，保证数据一致性

效果：员工表的dept_id必须是部门表里存在的id
· 不能给员工分配一个不存在的部门
· 部门还有员工时，不能直接删这个部门

注意：实际开发中很多公司不用物理外键，在代码层面保证

3.唯一 / 非空 / 自动增长
UNIQUE 唯一约束

列值不能重复，可以有一个NULL
比如用户名不能重复

NOT NULL 非空约束

这一列必须有值，不能是NULL
比如姓名不能为空

DEFAULT 默认值

AUTO_INCREMENT 自动增长

最常用组合：id int primary key auto_increment —— id自动递增，不用手动

4.索引：让查询变快的”目录”
类比：书的目录。不看目录要一页一页翻，看目录直接跳到那页

优点：
· 大大加快查询速度
· 表越大，效果越明显
· 分组排序也会变快

缺点：
· 占磁盘空间
· 增删改时要维护索引，变慢

该建索引的列：
· where 条件常用的列
· 表连接用的列
· order by 排序的列

不该建的列：
· 表很小、频繁增删改的列

给name列建普通索引
idx_ 开头是命名惯例

  • 查看和删除索引

查看表上有哪些索引
删除指定索引

补充：主键自带索引，不用单独建,唯一约束也会自动建唯一索引,新手不用纠结建多少索引，知道概念会用就行.

5.事务：一组操作，要么全成功，要么全失败
经典场景：转账。A给B转100，A减100，B加100，不能只成功一半。

A 原子性
不可分割，全做或全不做

C 一致性
前后数据总额不变

I 隔离性
事务之间互不干扰

D 持久性
提交后永久保存

TCL 语句
start transaction; 开启事务
commit; 提交（确认无误）
rollback; 回滚（出错了撤销）

例：

start transaction; – 1.开启事务
update account set money = money - 100 where name = ‘A’; – 2.A减100
– 如果这里出错了…
update account set money = money + 100 where name = ‘B’; – 3.B加100

commit; – 4.都成功了才提交
– rollback; – 出错了就回滚，前面的操作全部撤销

效果：如果中途报错没commit，rollback一下，A的钱不会少。
MySQL默认自动提交，一条SQL就是一个事务；手动开事务后要自己commit

6.用户与权限管理
生产环境不能所有人都用root，要建普通用户，给适当权限

– 1.创建用户
create user ‘zhangsan‘@’localhost’ identified by ‘123456’;

– 2.授权：只给查询权限，只能操作test库
grant select on test.* to ‘zhangsan‘@’localhost’;

– 3.刷新权限生效
flush privileges;

revoke 撤销权限；drop user 删除用户。本地开发用root就行，生产要严格控权。
