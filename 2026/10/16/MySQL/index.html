Windows 下 MySQL 8.0 安装、配置及 Workbench 连接实战

核心技术栈

MySQL 是一个基于客户端-服务器（C/S）架构的开源关系型数据库管理系统（RDBMS）。

1.关系型数据模型（Relational Model）

数据以二维表（Table）的形式组织，表与表之间可以通过主键（Primary Key）和外键（Foreign Key）建立关联关系。它使用结构化查询语言（SQL）作为交互接口。

2.C/S 架构与多线程模型

MySQL 由服务端守护进程（mysqld）和客户端工具（如 mysql CLI, Workbench, JDBC）组成。服务端采用多线程架构，每个客户端连接对应一个专属线程，配合线程池管理高并发请求。

3.插件式存储引擎（Pluggable Storage Engine）

这是 MySQL 区别于其他数据库（如 PostgreSQL）的核心架构特征。MySQL 的 SQL 层与底层数据存储解耦。默认且最常用的存储引擎是 InnoDB（支持 ACID 事务、行级锁、MVCC 多版本并发控制、B+树索引）；此外还有 MyISAM（表级锁，适合读多写少）、Memory 等引擎。

4.跨平台与多语言支持

采用 C/C++ 编写，支持 Windows、Linux、macOS 等主流操作系统。同时提供 C API、JDBC、ODBC、Python、Go 等几乎所有主流编程语言的驱动。

5.开源与双授权模式

遵循 GPL 协议，社区版完全免费，同时提供商业版授权及企业级支持。

**5.事务：一组操作，要么全成功，要么全失败**  
经典场景：转账。A给B转100，A减100，B加100，不能只成功一半。

A 原子性  
不可分割，全做或全不做

C 一致性  
前后数据总额不变

I 隔离性  
事务之间互不干扰

D 持久性  
提交后永久保存

>TCL 语句  
>start transaction; 开启事务  
>commit; 提交（确认无误）  
>rollback; 回滚（出错了撤销）  

例：   

start transaction; -- 1.开启事务  
update account set money = money - 100 where name = 'A'; -- 2.A减100  
-- 如果这里出错了...  
update account set money = money + 100 where name = 'B'; -- 3.B加100  

commit; -- 4.都成功了才提交  
-- rollback; -- 出错了就回滚，前面的操作全部撤销

**效果：如果中途报错没commit，rollback一下，A的钱不会少。  
MySQL默认自动提交，一条SQL就是一个事务；手动开事务后要自己commit**

**6.用户与权限管理**
生产环境不能所有人都用root，要建普通用户，给适当权限

-- 1.创建用户  
create user 'zhangsan'@'localhost'  identified by '123456';    

-- 2.授权：只给查询权限，只能操作test库    
grant select on test.* to     'zhangsan'@'localhost';  

-- 3.刷新权限生效  
flush privileges;  

**revoke 撤销权限；drop user 删除用户。本地开发用root就行，生产要严格控权。**
