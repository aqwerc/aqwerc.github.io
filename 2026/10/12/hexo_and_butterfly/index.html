Hexo博客搭建与 Butterfly 主题配置

一、核心技术栈

核心架构： Hexo 静态站点引擎

基于 Hexo 静态站点生成器,采用完全解耦的自动化交付链路，实现从本地编写到边缘节点分发的高效工作流.

  • 架构范式：基于 JAMstack (JavaScript, APIs, Markup) 架构的现代静态站点解决方案。
  • 渲染机制：采用 编译时预渲染（Build-time Pre-rendering / SSG），彻底剥离后端服务，将动态渲染开销前置到构建阶段。
  • 内容与表现分离：基于 MVC 变种架构，实现数据层（Markdown + YAML Front-matter）与视图层（Pug/EJS 模板 + Stylus/Sass）的完全解耦。

butterfly主题渲染

butterfly现代化且高度可定制的前端主题。集成 PJAX (PushState + AJAX) 实现页面无刷新加载，内置 Fancybox、懒加载与 PWA 支持，显著提升 FCP (First Contentful Paint) 指标。

  • 声明式模板编译 ：基于 Pug (原 Jade) 模板引擎，将 YAML 配置与页面数据进行语法级的编译转换，产出语义化的 HTML5 结构。
  • 配置驱动的视图渲染 (Config-Driven View Rendering)：通过 _config.butterfly.yml 实现视图层与逻辑层的完全解耦。主题支持在运行时（Runtime）根据配置项动态开启/关闭页面模块（如：文章目录、相关推荐、版权声明），实现高度的动态可插拔视图。
  • 多级布局系统 (Multi-tier Layout System)：采用 layout.pug 作为基础骨架，衍生出 post.pug、page.pug、archive.pug 等二级页面模板，通过条件渲染（Conditional Rendering）适配不同路由。

创建博客专用的 GitHub 仓库

登录 GitHub 后点击右上角 + 号 → Newrepository，创建一个特殊命名的仓库。

仓库名必须是：你的用户名.github.io GitHub Pages 会自动识别这种命名格式的仓库，把它作为你的个人主页发布。仓库创建后，访问 用户名.github.io 就能看到你的博客。

  • 选择 Public（公开）
  • 不要勾选 Initialize with README
  • 不要添加 .gitignore 和 License
  • 保持空仓库，后面由 Hexo 自动推送

Hexo：Node.js 驱动的静态博客框架

  • Hexo 是一个快速、简洁且高效的静态博客生成框架。
  • 你只需要用 Markdown 写文章，Hexo 就会自动生成静态网页。

安装Node.js

Hexo 是基于 Node.js 开发的框架，
必须先安装 Node.js 运行环境。
建议下载 LTS 长期支持版，稳定可靠。

  • 安装步骤
  1. 访问 nodejs.org 下载 LTS 版本
  2. 双击安装包，一路 Next 默认安装
  3. 勾选 “Add to PATH”（默认已勾选）
  4. 安装完成后重启 Git Bash

Hexo 常用命令总结

hexo项目目录结构

  • source/_posts/
    所有 Markdown 博客文章都放在这里，
    一篇文章就是一个 .md 文件。
  • themes/
    主题文件存放目录，
    第三部分的 Butterfly 主题就装在这里。
  • _config.yml
    站点全局配置文件，改标题、作者、部署地址
    都在这个文件里。

站点配置文件 _config.yml 详解

重点修改这几项

  • Site 区域

    语言设置为中文
  • URL 区域
    格式为 https://用户名.github.io
    Deployment 区域
  • 配置部署仓库地址
    repo 填你 GitHub 仓库的 SSH 地址。

四、常见报错处理与可能出现的问题

hexo init 是用来从零开始创建一个全新博客骨架的命令，它为了防止覆盖你现有的心血，强制要求目录必须是空的。

若原来有过远程连接，ssh密钥有可能匹配错误，若添加到github失败，则必须创建在英文路径下。

当前终端（CMD 或 PowerShell）不是以管理员身份运行的。系统拒绝普通用户在 D:\ 根目录或特定缓存目录下写入文件。

ssh无法登录，因端口被占用，需要更改端口连接设置。

因网络波动导致出现报错，需配置vpn进行解决。
